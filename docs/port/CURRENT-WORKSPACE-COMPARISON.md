# Current workspace versus Highway main — 16 October 2026

**This workspace is not yet a complete replacement for the original Highway application.** It has substantially more functionality than the separate repository examined in the earlier report. Claude, identity/payment adapters, executable workers, conversations, saved searches, brand/model pages and image uploads are present here. Their existence does not establish complete workflow parity.

## Confirmed defects fixed during this review

### Classified ownership checks allowed a missing owner

Migration `015` used `l.seller_id <> actor`. When a classified's lot has a NULL seller, SQL evaluates that comparison to NULL, so the `IF` did not reject an unrelated signed-in user's edit. Migration `016` had the same problem for an upload reservation. Both were reproduced with synthetic records through the public RPCs, not inferred from a string search. The original [ClassifiedPolicy](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/policies/classified_policy.rb) and [ClassifiedAdminPolicy](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/policies/classified_admin_policy.rb) require the relevant ownership/role authority.

The additive migration [`20261016001800_classified_ownership_and_upload_completion.sql`](../../supabase/migrations/20261016001800_classified_ownership_and_upload_completion.sql) uses `IS DISTINCT FROM` in both functions. Unrelated customers are rejected for NULL and different owners; explicitly provisioned staff can still manage unassigned records.

### Photo completion failed at runtime

The upload-completion RPC referenced `website_vehicle_upload.image_id` as if its local declaration were a SQL table reference. A legitimate draft owner's completion failed with `missing FROM-clause entry for table "website_vehicle_upload"`. Migration `018` uses a distinct `new_image_id` local variable. The regression now verifies completion, retry deduplication, cover assignment, persisted image linkage and rejection of another user's ticket.

These fixes are local source changes only. **Migrations `018`–`021` have not been applied to hosted Supabase.** Original migrations `001`–`017` were left unchanged.

## Additional gaps addressed on 16 October

### Direct purchases and after-sales checkout

[`PurchaseCheckout.jsx`](../../src/components/site/PurchaseCheckout.jsx), the purchase actions in `website-api`, and additive migration [`019`](../../supabase/migrations/20261016001900_purchase_checkout.sql) implement both source purchasing flows. Purchasable auctions use lifecycle `6`; after-sales purchase unsold auctions in lifecycle `10`. The original `/[locale]/auctions/:slug/purchases/new`, `/[locale]/auctions/:slug/after_sales/new` and `/[locale]/after_sales/:slug` URLs now reach localized React checkout. Eligible vehicle pages link to checkout. Public projections advertise eligibility without exposing reserve amounts.

The authenticated buyer receives a 15-minute server quote with vehicle price, buyer fee, applicable VAT and total. Confirmation binds to that buyer and quote; a row lock serializes against other buyers and the auction clock. Changed vehicle details, prices, fees or billing tax status require a new quote and fresh consent. Quote expiry is checked again after acquiring locks. Replaying the same successful request returns its receipt, including after quote expiry. Successful settlement records the buyer, marks the vehicle sold, rejects pending offers, queues invoices/notifications/catalogue refresh and remains unpaid until payment is verified.

Settlement also queues a comparable-sale report. The worker tokenizes the actual vehicle name, and a service-only RPC upserts the committed sale price into `reported_auctions`. Retrying this job does not create duplicate records. This closes the missing own-sale contribution to Claude's research dataset; external scraper promotion is still open.

Compatibility decisions are explicit: checkout reuses the replacement's verified identity, current terms and billing-address gates, rejects self-purchases, and requires a published, non-hidden listing with a positive SEK reserve and assigned seller. Other reserve currencies are rejected instead of silently treated as SEK (a missing currency retains the legacy SEK convention). The source purchase policies are less restrictive. Fees use the auction's configured buyer percentage and customer VAT so quote, settlement and invoice agree; both old controllers omit the buyer percentage when constructing `SoldState`, falling back to 7.5 even when the UI displays another rate. Direct purchases now explicitly record `sold`/`manual_sale`. The after-sale landing URL uses the checkout screen with a link back to full vehicle details. These differences need business acceptance before cutover.

Original custom mailer content, separate billing-recipient variations and Slack delivery remain part of the integration gap. Tests prove local state transitions and mocked adapters; they do not prove hosted provider delivery or simultaneous connections in a real Postgres deployment.

### Claude questionnaire input

[`questionnaire.ts`](../../supabase/functions/_shared/questionnaire.ts) replaces raw answer JSON with the original ordered Swedish question labels, `Ja`/`Nej`, four condition words, and follow-up descriptions only for negative answers. Car and motorcycle schemas are separate; unknown/removed fields and irrelevant follow-ups are omitted. Legacy question/answer lines retain their order. Invalid condition ratings are omitted instead of emitting a missing-translation string.

The 59 car fields and 48 motorcycle fields, including follow-ups, were extracted from the pinned GitHub schema and Swedish translations. [`import-highway-questionnaire.mjs`](../../scripts/import-highway-questionnaire.mjs) verifies both files against Git blob hashes before generating [`questionnaire-schema.json`](../../supabase/functions/_shared/questionnaire-schema.json).

Migration [`020`](../../supabase/migrations/20261016002000_questionnaire_ai_context.sql) includes the form type, lead vehicle name, odometer fallback and owner-count fallback in the AI snapshot. Only the owner count is extracted from existing CarInfo history; raw owner details are not sent to Claude. Applying a draft rejects changed questionnaire/fallback inputs. Existing pre-migration lot-text drafts require regeneration because their snapshot lacks this context. This ports input formatting, not the still-missing seller questionnaire editor or automatic text/summary orchestration.

### Live articles, pages, authors and article comments

Migration [`021`](../../supabase/migrations/20261016002100_live_editorial.sql) and [`EditorialPage.jsx`](../../src/components/site/EditorialPage.jsx) replace snapshot reads for `/[locale]/posts`, `/posts/:slug`, `/authors/:slug`, `/pages` and `/pages/:slug`. The public reader checks `published_at <= now()` on every request. Future/null publications, private parents and unpublished comments are excluded. Unpublished or deleted records cannot reappear through the old import.

The implementation follows the pinned [BlogPostsController](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/controllers/blog_posts_controller.rb), [BlogPost](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/models/blog_post.rb), [PagesController](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/controllers/pages_controller.rb), [AuthorsController](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/controllers/authors_controller.rb) and [15-item Pagy setting](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/config/initializers/pagy.rb). It preserves the first-page hero and exclusion from later pages, six allowed tags, author archives, language-specific slug lookup priority and blog requested-language → Swedish → English fallback. Pages and author biographies use English fallback. Translated article URLs redirect permanently, and metadata/language links use the selected live slugs. Published child pages and parent breadcrumbs, author portraits, publication dates, podcasts and rich text render in React. HTML is sanitized; comments render as text.

[`EditorialComments.jsx`](../../src/components/site/EditorialComments.jsx) and the `post_comment` API implement article comments/replies with the original immediate-publication rule from [CommentsController](https://github.com/biddershighway/highway/blob/0bae38c04fb0e6c9510d7bba659c151f456c095d/app/controllers/comments_controller.rb). The service-only write RPC resolves a confirmed, unbanned account, accepts only a published BlogPost and a published parent on that same post, and deduplicates retries. The browser cannot select an author, polymorphic type or publication status. This does not change the existing auction-comment moderation behavior. Source Slack notifications remain unported.

Reviewed Claude blog/page output is now read from the database after Apply, with no snapshot refresh required. Tests prove blog draft isolation and visibility after apply. Selectable source/target languages, automatic translated-slug creation, editorial CRUD, authenticated previews, theme spotlights, Instagram integration and automatic translation triggers remain open. Podcast visibility now requires publication time (the old index did not filter future media). Page archives also paginate; the old page index listed all roots. Deploy migration `021` and the updated API with the frontend; it has **not** been deployed here.

To rebuild the inventories from the downloaded source snapshot and fresh GitHub tree JSON:

```sh
node scripts/compare-highway-workspace.mjs /path/to/source-snapshot /path/to/github-tree.json
```

The script refuses a different source SHA. A future source update requires an explicit baseline update and another behavioral review. Its mapping is a static audit, not automated proof that all methods behave identically.

A workflow is complete only when its React/Next entry point, Supabase authorization and state transitions, required side effects, legacy URL/data compatibility and meaningful acceptance tests are all accounted for. The original request to port every function is **not complete** while the gaps above remain.
